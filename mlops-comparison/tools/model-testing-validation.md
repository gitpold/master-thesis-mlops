| **Decision** | **Option F: Giskard** for general model validation, additionally **Option H: Ragas** for LLM/RAG evaluation (together with **Langfuse** as monitoring & observability solution for LLM/RAG applications) |
|-------|-------|
| **Justification** | • Fiddler is dropped as there is no cloud onboarding information for the managed service and the on-premise installation would need a Kubernetes cluster (as well as as a paid license). <br>• Galileo is dropped as there is no cloud onboarding information for the managed service (although there has been a POC and talks with the provider by BD) and the on-premise installation would need a Kubernetes cluster (as well as as a paid license). <br>• Great Expectations is excluded as it does not provide model testing, but data testing. This could be relevant as an additional feature, but is not considered further here. <br>• Alibi Explain is a library for model testing and especially model explainability. As a Python package it can be used inside a project without any infrastructure concerns. Although this might be helpful in some cases, it seems not worth it to include this in a general setup. <br>•  Deepchecks is a library for validation of classical ML models, for LLM evaluation there is an additional paid solution. The Python package can easily be used for testing during development or inside of an CI pipeline without furthur infrastructure concerns. For a continuous validation of the models in production, there is also a Deepchecks Monitoring tool, which can be self-hosted but probably with an at least medium setup effort as the deployment setup has many dependencies (cannot be deployed as a single container) <br>• Giskard is a local library for model testing and seems to include testing of classical (tabular, CV) ML as well as LLMs and RAG systems. As a library it introduces no additional deployment concerns and can be used for local development or in a CI pipeline (generates evaluation reports as HTML) (for continuous monitoring and evaluation of LLMs there is only an additional paid, hosted service). Can make use of Ragas for additional metrics for evaluation of RAG systems. <br>• Arize Phoenix is an evaluation and observability/tracing solution for LLMs. The local library provides built-in evaluation metrics as well as the possibility to integrate Ragas. Additionally, it includes a monitoring component which can easily be self-hosted and deploed as a single container to store to store traces and visualize the evaluation metrics. Although Arize Phoenix is free, Arize is a paid service and there is thus no SSO option for the self-hosted version. <br>• Ragas is a Python library for RAG evaluation metrics and is widely used. As a locla  library it has no deployment/maintenance concerns. Additionally, it can be integrated with other validation and monitoring tools, like for example Giskard, Arize Phoenix, or Langfuse. <br>• alternative combination of **Option C: Deepchecks** for classical ML validation and **Option B: Arize Phoenix** (with **Option H: Ragas** ) for LLM/RAG evaluation and additionally **Option B: Arize Phoenix** as monitoring & observability solution for LLM/RAG applications was discarded  based on findings during implementation phase.|
